Бізнес-модель, економіка, метрики та технічна архітектура (курсова / інвестор)

Демо-дані на графіках — для ілюстрації; підставте реальну аналітику

1. Бізнес-модель

Тип: маркетплейс (двостороння платформа)

Платформа не володіє автопарком: з’єднує орендодавців і орендарів, забезпечує пошук, бронювання, прозорі правила та (у повній версії) платежі й виплати.
Джерело доходу: комісія з кожної успішної оренди (типово 5–10%).

Приклад: оренда 10 000 грн, комісія 5% → 500 грн виручки платформи; решта — власнику авто (за узгодженою схемою).

Основний процес (core flow)

  1. Власник додає авто в каталог (опис, фото, ціна, доступність).
  2. Клієнт обирає дати та бронює.
  3. Оплата через платіжну систему (цільовий сценарій).
  4. Платформа утримує комісію; решта — власнику.
  5. Після оренди: повернення депозиту, штрафи за прострочення / пошкодження.

Value proposition

Для клієнта: швидкий підбір авто, зрозумілі умови, безпечна оплата, підтримка та гарантії (як частина продукту).
Для власника: доступ до аудиторії без окремої реклами, автоматизація бронювань і календаря, менше ручної комунікації.

2. Unit economics

Revenue ≈ Orders × AvgPrice × Commission%

Приклад: 50 оренд/місяць, середній чек 3 000 грн, комісія 5% → 50 × 3000 × 0,05 = 7 500 грн/міс валової виручки платформи (до витрат на інфраструктуру, маркетинг, підтримку).

Стовпчики: ілюстрація «оренд × середній чек × ставка комісії» по місяцях (умовні цифри).

3. Графіки (must-have для презентації)

3.1 Growth — користувачі та бронювання в часі

3.2 Revenue — зростання доходу платформи

3.3 Funnel — воронка конверсії

Відвідувачі → перегляд авто → клік «Забронювати» → оплата. Нижче — горизонтальні стовпці (кількість на кроці).

3.4 Marketplace balance — авто vs активні клієнти

3.5 Unit economics breakdown — дохід, витрати, чистий результат

3.6 Retention — повторні візити / повторні оренди

5. Що підсилює роботу на захисті

SWOT

StrengthsWeaknesses
Автоматизація каталогу та бронювань; масштабована архітектура (сервіси окремо). Потрібні платіжка, страхування, модерація — без цього ризики для обох сторін.
OpportunitiesThreats
Зростання шерінгу авто; інтеграція з локальними страховими та СТО. Конкуренція OLX/прокатів; регуляторика; шахрайство та спори щодо стану авто.

Конкуренти (орієнтири)

  • Локальні прокати авто (офлайн + сайти).
  • Оголошення (OLX тощо) — без гарантій платформи та стандартизованого бронювання.
  • Міжнародні сервіси оренди (моделі C2C / B2C) — еталон UX і довіри.

Ризики

  • Шахрайство (фейкові оголошення, підроблені документи).
  • Пошкодження авто, суперечки щодо депозиту.
  • Скасування та простої — потрібна політика штрафів/компенсацій.

Монетизація (розширена)

  • Комісія з угоди (основа).
  • Платне підвищення оголошення в топі видачі.
  • Партнерські програми зі страхуванням, КАСКО, допомогою на дорозі.

6. Технічний зріз проєкту (для слайду «реалізація»)

  • Клієнт: React, запити на єдиний базовий URL API (/api).
  • Gateway: Node.js backend — маршрутизація до мікросервісів, BFF для бронювань.
  • Сервіси: user-service (акаунти, JWT + Google), car-service (каталог, UUID), rental-service (оренди), reporting-service (звіти/штрафи — за наявності).
  • Дані: окремі БД під домени (PostgreSQL), узгоджені DTO та ідентифікатори UUID.
