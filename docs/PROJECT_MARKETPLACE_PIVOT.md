# Зміна суті проекту: маркетплейс оренди авто

## Нова ідея

- **Орендарі** — реєструються, шукають авто, бронюють, оплачують.
- **Орендодавці** — реєструються, додають свої машини, **задають свої ціни**, приймають бронювання.
- Платформа типу Turo / Getaround: не одна компанія з автопарком, а ринок «власник ↔ орендар».

---

## Простіше новий проект чи переробити цей?

**Рекомендація: переробити цей проект.**

### Чому переробити вигідніше

1. **Мікросервіси вже під маркетплейс**
   - **user-service**: ролі `renter`, `owner`, `both`, `admin` — саме те, що потрібно.
   - **car-service**: авто з `ownerId`, ціноутворення (денна/тижнева/місячна, депозит) — орендодавець публікує авто і сам ставить ціни.
   - **rental-service**: прокати за `carId` + `renterUserId` — орендар бронює авто власника.

2. **Є готовий код**
   - Авторизація, каталог авто, прокати, звіти, патерни (Singleton, Factory, Builder тощо). Це можна адаптувати, а не писати з нуля.

3. **Що реально міняється**
   - Логіка та UX: хто що бачить і що може робити (орендар vs орендодавець).
   - Реєстрація з вибором ролі (орендар / орендодавець).
   - Кабінети: «Мої авто» + «Мої ціни» для власника, «Бронювання» для орендаря.
   - Джерело даних: поступово підключати frontend до user/car/rental мікросервісів замість лише моноліту.

4. **Новий проект означав би**
   - Дублювання інфраструктури (БД, auth, API).
   - Повторна реалізація того, що вже є в мікросервісах.
   - Більше часу без реальної вигоди.

## Що вже є під маркетплейс

| Частина | Що є | Під маркетплейс? |
|--------|------|-------------------|
| user-service | Ролі renter / owner / both, профіль, документи | Так |
| car-service | Авто з ownerId, pricing (daily/weekly/monthly, deposit) | Так |
| rental-service | Прокати carId + renterUserId, complete/cancel | Так |
| Моноліт backend | Користувачі (admin/manager/employee), клієнти, авто (id number), прокати | Зараз модель «одна компанія» |
| Frontend | Реєстрація без ролі, адмін-панель (машини/клієнти/прокати), сторінка «мої прокати» | Потрібна адаптація під орендар/орендодавець |

## Що змінити (план переробки)

### 1. Реєстрація та ролі

- При реєстрації: вибір **«Орендар»** / **«Орендодавець»** (або «Обидва»).
- У backend або в user-service зберігати роль (renter/owner/both); для моноліту — або додати поле role до users, або поступово переходити на user-service.

### 2. Орендодавець

- Кабінет орендодавця:
  - **Мої авто** — список своїх авто (з car-service: `GET /api/cars/owner/:ownerId`).
  - **Додати авто** — форма (марка, модель, рік, категорія, фото, **свої ціни**: денна/тижнева/депозит).
  - **Мої бронювання** — прокати по моїм авто (rental-service: по carId або через список своїх carId).
- Ціни задає тільки власник авто (вже підтримано в car-service).

### 3. Орендар

- Головна / каталог — перегляд усіх авто (car-service: `GET /api/cars`, пошук).
- Сторінка авто — деталі, ціни власника, календар зайнятих днів (rental-service: `GET /api/rentals/car/:carId/booked-dates`).
- **Забронювати** — створення прокату (rental-service: `POST /api/rentals` з carId, renterUserId, датами).
- **Мої бронювання** — історія та поточні прокати (rental-service: `GET /api/rentals/renter/:renterId`).

### 4. Адмін (платформа)

- Залишити адмін-панель для модерації, скарг, звітів (користувачі, авто, прокати) — можна довго підключати до моноліту або до мікросервісів.

### 5. Підключення до мікросервісів

- **Варіант A (швидко):** фронт як раніше ходить у моноліт; у моноліті додати проксі до car-service / user-service / rental-service і поступово переносити ендпоінти (наприклад, «мої авто» → car-service, «бронювання» → rental-service).
- **Варіант B:** фронт частину запитів відправляє напряму на user/car/rental сервіси (через один gateway або різні base URL). Потрібно узгодити формати (наприклад, id: number vs UUID).

Спочатку достатньо змінити **концепцію в інтерфейсі** (реєстрація з роллю, екрани для орендаря та орендодавця) і підключити один-два потоки до мікросервісів; решту можна переносити крок за кроком.

## Висновок

- **Простіше і швидше — переробити цей проект**: мікросервіси вже під маркетплейс, потрібні зміни в логіці та UI та підключення фронту до цих сервісів.
- Новий проект мав би сенс лише якщо б ти повністю відмовлявся від поточної архітектури та стеків і починав з чистого аркуша — це більше роботи без виграшу в гнучкості для твоєї ідеї.

Якщо хочеш, наступним кроком можу запропонувати конкретні зміни в коді: наприклад, реєстрація з вибором «Орендар»/«Орендодавець» і базова структура кабінету орендодавця (Мої авто + додати авто з цінами).
